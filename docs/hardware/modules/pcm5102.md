# PCM5102A I2S DAC (GY-PCM5102 module)

## Module pins

This GY-PCM5102A board has two pin rows plus a 3.5 mm jack.

**I2S + power row:**

| Pin | Function |
| --- | --- |
| SCK | System clock — **tie to GND** (internal PLL, 3-wire I2S) |
| BCK | I2S bit clock |
| DIN | I2S data in |
| LCK | LRCK / word select |
| GND | Ground |
| VIN | 3.3–5 V supply |

**Analog + config row:**

| Pin | Function |
| --- | --- |
| LROUT | Left analog out |
| AGND | Analog ground |
| ROUT | Right analog out |
| AGND | Analog ground |
| A3V3 | 3.3 V analog reference out |
| FMT / XSMT / DEMP / FLT | Config pins (set via the H-pads below) |

Line out: 3.5 mm stereo jack (+ L / G / R pads).

## Config jumpers (solder pads, back of board)

> ⚠️ **The H/L silkscreen on our board is inverted — do NOT trust the labels.** On the
> unit on hand, measuring continuity showed the pad printed "H" goes to **GND** and the
> pad printed "L" goes to the **3.3 V** rail (the opposite of what the labels say). Setting
> the jumpers by label left XSMT muted and FMT in the wrong format.
>
> **Before soldering any jumper, confirm with the multimeter** (continuity, board off):
> probe each rail pad against a known GND and against VIN to learn which side is actually
> GND and which is 3.3 V. Then bridge by **voltage**, not by the printed H/L. After
> soldering, power up and verify the target pin reads the right voltage (XSMT ≈ 3.3 V,
> FMT ≈ 0 V). See [Notes & gotchas](#notes--gotchas) for the full check.

Four `H_L` pads tie each config pin High or Low. For standard I2S playback:

| Pad | Pin | Set to | Meaning |
| --- | --- | --- | --- |
| H1L | FLT | L | Normal latency filter |
| H2L | DEMP | L | De-emphasis off |
| H3L | XSMT | H | Un-muted (mute off) |
| H4L | FMT | L | I2S format |

Also tie **SCK → GND** (header pin) so the chip uses its internal PLL.

### In plain language

**The SCK pin (master clock) → tie it to GND.** The chip has two clock concepts and the
names trip people up. BCK, LRCK, and DIN are the three audio wires you run to the ESP32.
**SCK is separate** — it's a master clock *input* the DAC needs to time its converter.
The ESP32 could generate that clock, but the PCM5102 can instead make its own **internally
(a built-in PLL)** — and the way you switch that on is by **grounding the SCK pin**. Leave
SCK floating and the chip waits for a clock that never arrives → **no sound** (the #1
"why is it silent" mistake). So: tie **SCK → GND**, and the 3-wire I2S is enough.

Two ways to do it, pick one (not both — redundant, though harmless):
- **A jumper wire** from the SCK header pin to a GND pin, or
- **The on-board solder bridge** next to SCK: a small pad pair where (confirmed with the
  multimeter) one pad reads continuity to **SCK** and the other to **GND**. Join them with
  a drop of solder. After soldering, verify the two pads now connect to each other, and
  that **SCK ↔ GND** shows continuity.

Either way, **SCK only ever goes to GND — never to an ESP32 GPIO.**

**The four jumpers (H1L–H4L) pick the playback "mode."** Each pad group is a tiny
three-point pad: the **center** is the config pin, one end is **H** (3.3 V), the other is
**L** (GND). You bridge the center to whichever side you want with solder. Set them like so:

| Pad | Pin | Bridge center to | Meaning |
| --- | --- | --- | --- |
| H1L | FLT | **L** | Normal filter |
| H2L | DEMP | **L** | De-emphasis off |
| H3L | XSMT | **H** | Un-muted ← the important one |
| H4L | FMT | **L** | Standard I2S format |

So three of them go to **L** and only **H3L (XSMT) goes to H**. Most GY-PCM5102 boards ship
already set this way, so you usually **don't need to touch them** — check first with the
multimeter (continuity from the center pad to the H or L side tells you how it's currently
set). The one that actually matters is **XSMT: it must be HIGH (un-muted)**, or you get
total silence even when everything else is correct.

## Notes & gotchas

- The internal PLL means **3-wire I2S** (BCK, LCK, DIN) is enough — we don't wire MCLK. This only works if **SCK is grounded**.
- **XSMT must be high**, or the output stays muted. Most GY boards handle this, but verify.
- This DAC's line out is what provides clean **headphone/line output** — the PAM8403 (and the MAX98357A) are BTL speaker amps and can't drive headphones directly.
- **Line-level out — don't drive a speaker/headphones straight from VOUTL/VOUTR**; buffer or amplify (this is why the PAM8403 follows it for the speaker). Source: Cirkit guide above.
- **Starter tone test (later):** output a sine wave over I2S. The Cirkit guide's example uses the generic Arduino `I2S.h`, which won't run on the ESP32-S3 — use the core's **`ESP_I2S`** library (`#include <ESP_I2S.h>`) and set the pins to our BCK/LRCK/DIN. Keep I2S clocks clean.
- Connections to the ESP32-S3 → see [../wiring.md](../wiring.md#connections).
